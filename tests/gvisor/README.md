# gVisor syscall compatibility tests

This standalone entry builds unmodified upstream C++ syscall tests and runs the
same static ARM64 ELF files on native Linux and Trames. It does not build/run
`runsc`, fetch Go toolchains, or introduce a production runtime dependency.

The default pilot is **11 groups / 408 enabled cases**. The optional broad
build below discovers the pinned Linux C++ BUILD targets. Pilot groups: brk, clock_getres, clock_gettime, dup, eventfd, getrandom, pipe, epoll,
mmap, futex and uname. Upstream disabled tests remain disabled; upstream runtime
skips and reference failures are reported separately. No expectation is relaxed
for Trames, and `TEST_ON_GVISOR`/save-restore mode are unset.

See [the first Mac results and fix/rerun checkpoint](../../docs/validation/gvisor-syscalls-20261117.md#fix-and-rerun-checkpoint).

The [network ABI repair checkpoint](../../docs/validation/gvisor-network-abi-fixes-20261117.md)
records a complete ancillary-message matrix and focused network/security reruns
after the broad inventory.
The [ancillary completion checkpoint](../../docs/validation/gvisor-unix-ancillary-20261117.md)
closes its remaining 84 Unix control-message failures and expands the message API check.

The [Unix endpoint checkpoint](../../docs/validation/gvisor-unix-endpoints-20261119.md)
repairs RAW creation, shutdown/readiness, zero-length receives, reset errors and
datagram reconnect/accept semantics, with paired hot-path measurements.

The [Unix flow-control checkpoint](../../docs/validation/gvisor-unix-flow-control-20261119.md)
adds real addressed-sender accounting, receive completion, socket options and

runs without filtered tests, and preserves the complete 6194-case result.

## Build on native ARM64 Linux

Install a C++17 compiler, CMake, Ninja, Python 3 and ordinary static glibc/libstdc++
development libraries. The checksum-pinned source archives are described in
`upstream.json`. Abseil, GoogleTest and Benchmark use gVisor's dependency versions.
The small Bazel 6.5 runfiles implementation preserves the original runfiles API;
its public header is generated by the upstream copy recipe. The original
errno-preserving allocator, test main and test utilities are retained.

```sh
python3 tests/gvisor/prepare.py --output /tmp/gvisor-build --build --jobs 4 \
  --export /tmp/gvisor-artifacts/bin
```

`--cache DIR` reuses already verified archives, including a read-only cache when
all inputs are present. Only test sources, their small libraries and selected
binaries are built. The command rejects edited existing source files rather
than replacing them, checks static ARM64 ELF outputs, and writes a source/compiler/
binary hash record. A current build/cache is well below 1 GiB.

## Native reference

Run in a disposable Linux CI machine. Root is needed for fresh mount, PID, UTS,
IPC and network namespaces. Each test is PID 1 in a new namespace; its working
directory is temporary. The driver sets its own FD limit to 1,048,576, required
by the upstream 66,000-FD stress tests. This does not change global kernel limits.

```sh
sudo python3 tests/gvisor/run.py native --binaries /tmp/gvisor-artifacts/bin \
  --output /tmp/gvisor-native --timeout 20
```

The resulting `plan.json` contains exact case names and binary hashes. Default
selection runs every enabled case in the listed groups. An explicit
`--max-cases-per-suite 20` samples a pilot; the plan records this restriction.
`--case-filter 'BrkTest.*'` selects focused original tests.

## Trames comparison on Mac

Copy the same `bin` directory and reference plan to the Mac. Use the Dev runner
and a verified Alpine archive; static tests use the same glibc regardless of the
rootfs. Each case starts a fresh Trames runtime process in a dedicated registry,
with six CPUs, an 8 GiB lazy memory budget, no windows/GPU/audio/network, and all
host interoperability permissions denied. Normal product environments are not
used. Output is read from the stopped store through the existing owner VFS path.

```sh
python3 tests/gvisor/run.py trames --binaries /tmp/gvisor-artifacts/bin \
  --reference /tmp/gvisor-native/plan.json \
  --runner '/path/to/Trames Dev.app/Contents/MacOS/trames-mac-run' \
  --rootfs /path/to/alpine-minirootfs.tar.gz --output /tmp/gvisor-trames \
  --timeout 20
python3 tests/gvisor/compare.py --native /tmp/gvisor-native \
  --trames /tmp/gvisor-trames --output /tmp/gvisor-comparison
```

For tests with additional interpreter dependencies, pass `--custom-rootfs`
alongside `--rootfs PATH` to import a prepared ARM64 Linux archive. For
example, `ExecTest.InterpreterScript` uses the original runfile with
`#!/bin/bash` and requires Bash plus its dynamic loader and libraries. The
runner records the archive digest. The mount and rename suites remount the isolated guest sysfs
with the same writable mount flags as the native reference.

Each output directory must be new. Case stdout/stderr and original GoogleTest
XML remain available. Timed-out processes are terminated as their own process
group; abnormal exits/missing XML remain failures, never successful skips.
The disposable Trames store is removed on normal completion; `--keep-registry`
retains it for debugging. No application build/deployment is needed.

`--reuse PREVIOUS_OUTPUT` reuses passing/skipped cases only with matching binary
and environment fingerprints; failures are retried. Reused evidence remains
linked to its original logs. `compare.py --native-retry RETRY_OUTPUT` can overlay
a documented reference-fixture retry and checks binary identities/case sets.
The strict pass fraction uses only native-passing cases as its denominator;
unexpected Trames skips are not counted as passes.

## Limits

This is a compatibility diagnostic, not a latency benchmark or conformance claim.
Cold startup/namespace overhead is included in timings. Privileged tests must
remain isolated. Adding more groups may require their original helper binaries,
runfiles, mounts, capabilities, network fixtures or UAPI headers; use the upstream
BUILD graph as the reference. No unsupported test should be silently omitted.

For interpreter coverage on the development host, use the product
`trames-run` CLI with the same original reference plan and binaries:

```sh
python3 tests/gvisor/interpreter.py --runner /path/to/trames-run \
  --rootfs /path/to/alpine-minirootfs.tar.gz --binaries /tmp/gvisor-artifacts/bin \
  --reference /tmp/gvisor-native/plan.json --output /tmp/gvisor-interpreter \
  --suites mount --case-filter 'MountTest.UserNamespaceSysfs*'
```

The interpreter harness copies a clean imported store for each case and uses
the same guest setup as the Mac harness, including writable sysfs for mount and
rename. It retains original per-case XML and the executable hashes. Interpreter
results on the development host do not exercise a physical iPad.

## Broad Linux/ARM64 coverage

`--expanded` resolves the original `cc_binary`/`cc_library` dependency graph
without evaluating arbitrary Starlark. It selects ARM64/Linux source branches,
links the original alwayslink test registrations, and preserves ordinary lazy
static extraction for `test_main` (some upstream programs supply their own main).
Unknown dependencies and runfiles are explicit build blockers. No test assertion
or upstream source is rewritten. `expanded.json` records the selected sources,
helpers, blockers and the one compiler compatibility adjustment: Ubuntu fortify
must be disabled for the upstream sticky-bit test's intentional missing-mode
errno probe. Native and Trames use the same resulting ELF.

```sh
python3 tests/gvisor/prepare.py --output /tmp/gvisor-expanded --expanded \
  --build --jobs 4 --export /tmp/gvisor-artifacts/bin
cc -O2 -Wall -Wextra -Werror -static tests/gvisor/native-init.c \
  -o /tmp/gvisor-native-init
sudo python3 tests/gvisor/batch.py native \
  --binaries /tmp/gvisor-artifacts/bin --output /tmp/gvisor-native-expanded \
  --native-init /tmp/gvisor-native-init --jobs 4 --timeout 20 \
  --suite-timeout alarm=60 --suite-timeout itimer=90 --time-budget 1800
python3 tests/gvisor/inventory.py --binaries /tmp/gvisor-artifacts/bin \
  --output /tmp/gvisor-inventory.json
```

The tiny native init owns PID/session 1, enables only loopback inside the
reference network namespace, and runs each test as PID 2. The harness temporary
ancestor is searchable (0755) so tests can deliberately drop UIDs and exercise
their own directory permissions. Test roots/mounts/PID/IPC/UTS/network state are
private to the disposable CI VM, not the Mac or production environments.
Native reference failures, skips and timeouts do not count as Trames successes
or valid Linux-passing comparison cases. Keep exported binaries immutable while
references/guests are running.

Copy the same artifacts and reference output to the Mac, then:

```sh
python3 tests/gvisor/batch.py trames --binaries /tmp/gvisor-artifacts/bin \
  --reference /tmp/gvisor-native-expanded \
  --reference-timings /tmp/gvisor-native-expanded \
  --runner '/path/to/Trames Dev.app/Contents/MacOS/trames-mac-run' \
  --rootfs /path/to/alpine-minirootfs.tar.gz --output /tmp/gvisor-trames-expanded \
  --fresh-store --chunk-size 50 --jobs 4 --cpus 2 --timeout 5 \
  --suite-timeout alarm=65 --suite-timeout itimer=95 --time-budget 1800
python3 tests/gvisor/normalize.py --source /tmp/gvisor-trames-expanded \
  --output /tmp/gvisor-trames-audited
python3 tests/gvisor/compare.py --native /tmp/gvisor-native-expanded \
  --trames /tmp/gvisor-trames-audited --output /tmp/gvisor-expanded-comparison
```

This mode uses a Trames-only bridge with NAT disabled. It does not bind test
listeners to the host network. Each worker owns a new registry. The imported
store is APFS-cloned before every process, including isolated retries. The
original GTest fixtures run chunks of at most 50 selected names; no enabled
case is sampled away. A full original XML report and the matching case set are
required for every passing result. Stdout is used only to split an aborted or
hung chunk into retries, never as passing evidence. A singleton group/case
remains available with `--chunk-size 1`. A global GTest fixture failure is
separate from an assertion failure or a successful skip.

The active-case watchdog extends the base timeout for known native-passing slow
cases to `max(base, min(90, 3 * native_seconds + 2))`. Explicit alarm/itimer
allowances cover their original 20–30-second waits. Timing is only a timeout
allowance, not a performance comparison. Unfinished work under `--time-budget`
stays `not_run_budget`; disk pressure stays `disk_limit`/`not_run_disk_limit`.
The default disk floor is 8 GiB. Neither condition becomes a pass or skip.

Batch partitions balance complete case lists, splitting large parameterized
groups across workers without duplication. Raw worker plans, XML/stdout/stderr
and merged outcomes remain linked. Changing the worker count or selecting a
subset of suites reuses each matching case by name. A second continuation still
points back to the original XML. Missing or mismatched passing XML triggers a
fresh run. Fully cached partitions skip guest setup. With matching
runtime/ELF/rootfs/network/CPU/runfile fingerprints, use `--reuse OLD_BATCH`.
`--reuse-completed` also retains unchanged, already confirmed assertion/abort
results; timeouts are retried. Completed singleton results can be reused by a
chunked continuation. Keep the previous raw evidence directory.

The broad runner currently automates Mac HVF only. iPad execution, upstream
DISABLED cases, other architectures and gVisor-only save/restore modes remain
separate coverage, irrespective of how many Linux syscall cases pass.

`normalize.py` independently checks every reported pass against its exact saved
XML case and exit status. It can refine an old `mismatched_result` containing a
GTest `NonTestSuiteFailure` into `fixture_failed`; neither becomes a pass. This
postprocessing does not alter raw logs, original assertions or executables.
`summarize.py` exports a complete per-case CSV and compact group/family JSON.
The harness evidence guards can be run without rebuilding any product:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests/gvisor -p '*_test.py'
```
