# gVisor syscall compatibility tests

This standalone entry builds unmodified upstream C++ syscall tests and runs the
same static ARM64 ELF files on native Linux and Trames. It does not build/run
`runsc`, fetch Go toolchains, or introduce a production runtime dependency.

The initial scope is **11 groups / 408 enabled cases**, not the entire upstream
suite: brk, clock_getres, clock_gettime, dup, eventfd, getrandom, pipe, epoll,
mmap, futex and uname. Upstream disabled tests remain disabled; upstream runtime
skips and reference failures are reported separately. No expectation is relaxed
for Trames, and `TEST_ON_GVISOR`/save-restore mode are unset.

See [the first Mac results and fix/rerun checkpoint](../../docs/validation/gvisor-syscalls-20261117.md#fix-and-rerun-checkpoint).

## Build on native ARM64 Linux

Install a C++17 compiler, CMake, Ninja, Python 3 and ordinary static glibc/libstdc++
development libraries. The checksum-pinned source archives are described in
`upstream.json`. Abseil, GoogleTest and Benchmark use gVisor's dependency versions.
The small Bazel 6.5 runfiles implementation preserves the original runfiles API;
its public header is generated by the upstream copy recipe. The original
errno-preserving allocator, test main and test utilities are retained.

```sh
python3 tests/gvisor/prepare.py --output /tmp/gvisor-build --build --jobs 4 \
  --export /tmp/gvisor-artifacts/bin
```

`--cache DIR` reuses already verified archives, including a read-only cache when
all inputs are present. Only test sources, their small libraries and selected
binaries are built. The command rejects edited existing source files rather
than replacing them, checks static ARM64 ELF outputs, and writes a source/compiler/
binary hash record. A current build/cache is well below 1 GiB.

## Native reference

Run in a disposable Linux CI machine. Root is needed for fresh mount, PID, UTS,
IPC and network namespaces. Each test is PID 1 in a new namespace; its working
directory is temporary. The driver sets its own FD limit to 1,048,576, required
by the upstream 66,000-FD stress tests. This does not change global kernel limits.

```sh
sudo python3 tests/gvisor/run.py native --binaries /tmp/gvisor-artifacts/bin \
  --output /tmp/gvisor-native --timeout 20
```

The resulting `plan.json` contains exact case names and binary hashes. Default
selection runs every enabled case in the listed groups. An explicit
`--max-cases-per-suite 20` samples a pilot; the plan records this restriction.
`--case-filter 'BrkTest.*'` selects focused original tests.

## Trames comparison on Mac

Copy the same `bin` directory and reference plan to the Mac. Use the Dev runner
and a verified Alpine archive; static tests use the same glibc regardless of the
rootfs. Each case starts a fresh Trames runtime process in a dedicated registry,
with six CPUs, an 8 GiB lazy memory budget, no windows/GPU/audio/network, and all
host interoperability permissions denied. Normal product environments are not
used. Output is read from the stopped store through the existing owner VFS path.

```sh
python3 tests/gvisor/run.py trames --binaries /tmp/gvisor-artifacts/bin \
  --reference /tmp/gvisor-native/plan.json \
  --runner '/path/to/Trames Dev.app/Contents/MacOS/trames-mac-run' \
  --rootfs /path/to/alpine-minirootfs.tar.gz --output /tmp/gvisor-trames \
  --timeout 20
python3 tests/gvisor/compare.py --native /tmp/gvisor-native \
  --trames /tmp/gvisor-trames --output /tmp/gvisor-comparison
```

Each output directory must be new. Case stdout/stderr and original GoogleTest
XML remain available. Timed-out processes are terminated as their own process
group; abnormal exits/missing XML remain failures, never successful skips.
The disposable Trames store is removed on normal completion; `--keep-registry`
retains it for debugging. No application build/deployment is needed.

`--reuse PREVIOUS_OUTPUT` reuses passing/skipped cases only with matching binary
and environment fingerprints; failures are retried. Reused evidence remains
linked to its original logs. `compare.py --native-retry RETRY_OUTPUT` can overlay
a documented reference-fixture retry and checks binary identities/case sets.
The strict pass fraction uses only native-passing cases as its denominator;
unexpected Trames skips are not counted as passes.

## Limits

This is a compatibility diagnostic, not a latency benchmark or conformance claim.
Cold startup/namespace overhead is included in timings. Privileged tests must
remain isolated. Adding more groups may require their original helper binaries,
runfiles, mounts, capabilities, network fixtures or UAPI headers; use the upstream
BUILD graph as the reference. No unsupported test should be silently omitted.

The binaries can also be transported to iPad for interpreter coverage, but this
entry currently automates Mac HVF only; no physical iPad pass is implied.
