# FUSE 领域收尾（2026-11-26）

本轮按产品仓库实施清单 02 的完成标准收尾：原版 guest daemon、普通 Linux 客户端、映射与传输、错误／并发／卸载生命周期，以及实际传输和普通负载测量。没有新增协调／服务线程，也没有轮询消息总线。共享实现使用既有平台无关资源，Apple 专用实现仍留在原 target cfg 内。

## 本轮补齐

新增真实程序验收发现，FIFO 和设备节点已有行为，而 Unix pathname socket 的 `bind` 仍返回 EOPNOTSUPP。现将绑定、连接、定址 datagram、sendmsg／sendmmsg 以及 io_uring BIND／CONNECT 接入现有 NamespaceWork／FileWork。接受后的原 OFD、路径、凭据及 daemon 请求随等待保留，不经同步回退重查已接受的路径；必要 native 工作仍由原执行器完成。

绑定只对原 socket 保留 Linux 所需的排他准入。竞争者订阅原资源并交还执行槽；取消释放自己的准入，不替其他调用发布结果。成功绑定的 socket 保留原 FUSE inode 和 mount 使用权：弱 inode 缓存、再次 LOOKUP、FD 关闭复用不会丢失绑定；活跃 socket 阻止普通卸载，最终关闭释放挂载和连接。原私有卷锁的恢复测试改为恢复独立的 checkpoint 副本，另明确验证活跃 socket 仍保留原卷锁。

错误回复与资源等待分开。daemon 返回的 EAGAIN 是路径操作的终态 errno；普通调用和批量发送不把它当作队列空间等待，io_uring 发布原 CQE，不重新发起 LOOKUP／MKNOD。定向回归覆盖 bind、connect、sendto、sendmsg、sendmmsg 和两种 ring 操作。

## 输入与验证

普通客户端只使用 Linux syscall，不实现 FUSE 协议。原版工具为此前固定的 libfuse 3.14.0 `passthrough`／`passthrough_ll`，静态 ELF、Alpine rootfs 与客户端在各后端按 SHA-256 核对。三种配置为低层、实际激活 WRITEBACK_CACHE 的低层及高层；Trames 使用 1／2／4 CPU。每组检查十类功能及三项卸载／daemon 退出行为，新增特殊文件、Unix socket、跨 FUSE 链接回普通文件系统、批量 datagram 和 ring socket 路径。

最终 Rust 单元结果按身份和最后修改范围合并：Apple **1,683 通过／2 忽略**，Linux ARM64 **1,691／2**，无失败；通过项不重复计数。两个宿主全工作区严格检查及最后 Linux 调用层的补查通过，执行边界检查通过。未变的核心、图形、网络及先前完整 CI 结果按来源复用，没有重复全量 CPU／图形或 254 组 gVisor。

最终产物的原版 gVisor FUSE／映射／AIO／ring／传输等 421 个身份，2 CPU 原始结果为 **410 通过／10 跳过／1 失败**。唯一失败仍是已有的 `IOUringTest.ThreeREADVSingleEnterTest`：第二项先完成长度 26 的请求，原测试按 CQE 数组位置要求长度 17。[Linux io_uring 文档](https://man7.org/linux/man-pages/man7/io_uring.7.html) 允许异步请求乱序完成，结果应按 `user_data` 关联。原始失败保留；只对这一原版身份按既有 **1 CPU 前提**复核通过，没有强制运行时固定完成顺序。真实客户端已对三项完成逐个核对 user_data、长度、内容及不重复，在原生三配置及 Trames 两后端各九组通过。
