# Guest software perf（2026-11-27）

本轮完成 08 的选定软件事件与原版工具路径。普通 ABI、单槽、原版工具、异步续接分类、产品组合及采样密度验证通过，支持边界和实测开销见下文与 [JSON 回执](perf-20261127.json)。这里不宣布硬件 PMU 或全部 Linux perf 功能可用。

## 实现与边界

| 范围 | 实现 |
| --- | --- |
| 软件事件 | CPU-clock、task-clock、page-faults、context-switches、cpu-migrations、minor/major faults、dummy；没有真实生产者的 alignment/emulation、BPF-output、cgroup-switches 和硬件 PMU 继续拒绝 |
| 原资源 | task、task+CPU、CPU-wide、cgroup+CPU；保留原任务、逻辑 CPU、cgroup 身份，关闭／退出／同名重建不重定向旧观察者 |
| 时间 | 沿用原任务执行记账。普通 task 的 enabled/running 使用任务上下文时间；task+CPU 的 enabled 使用完整任务上下文，running 只累计选定 CPU；CPU-wide clock 包含 idle。CPU 过滤时钟只由实际执行它的原 actor 启停，不根据停用观察前的旧 CPU 信息启动；没有把普通任务睡眠时间改成 enabled 时间 |
| 计数生产者 | 原执行者分配／换出／迁移，以及原 guest 页准入、匿名零页／COW、文件缓存和实际后端 IO；驻留页重复访问不累计冷缺页。异步内核复制沿用原调用阶段，不把宿主其他进程的页故障导入 guest |
| 采样 | 现有执行边界、解释器按原执行者实测指令速率校准的有界片段、HVF 已有执行定时器；时钟事件保留 10µs 下限。频率与每 CPU 开销预算沿用动态 sysctl，支持 `perf_cpu_time_max_percent`。开销窗口由原执行者推进，不启动采样／定时／协调线程 |
| 元数据 | 原 guest COMM、COMM_EXEC、MMAP/MMAP2、FORK、EXIT 和 sample_id_all；CPU/cgroup 观察者使用原任务 exec 代次，不持有任务／Files 图 |
| 生命周期 | 继承和 enable-on-exec／重新 ENABLE 激活原生产者。非用户可 dump 的 exec 撤销旧 context，旧 FD 冻结，存活任务可以新开事件；原任务退休先冻结父 context，新 CPU 过滤器不能复活它，通知在过滤器／组锁外进行；不提前结束内存压力资源 |
| 映射 | 控制页可写、数据页写入 SIGBUS，no-fork/no-expand/no-dump；当前 Linux 的 may_split 约束，整体移动可用，未改变权限的局部 mprotect 不拆分 VMA；沿用 Linux 对已有 ring 别名的记账方式 |
| 平台 | Runtime 使用现有平台中立接口；HVF 截止时间落在已有 Apple 后端／target cfg 内。没有引入生产协调、采样或资源服务线程 |

计数的 CPU 时间是 Runtime 原有执行记账，不是宿主 PMU 的指令／周期计数。软件采样只记录当下边界，不补造历史样本；兼容内核没有 guest EL1 PC，内核样本明确为 `MISC_KERNEL`／IP 0，禁止把 guest EL0 或宿主 Rust 地址当作内核文本。原生函数仍以真实可用边界为准，不承诺 precise_ip。无法解析的地址字段保持 0，不能用于缺页虚拟地址定位。CPU-wide 的 idle 时间可计数；没有执行者边界的空闲时段不伪造 idle PC 样本。

硬件事件、callchain、用户／中断寄存器与栈、branch stack、AUX、硬件精确 IP 等不在此次支持范围。原版 perf 默认请求的 ksymbol/BPF 元数据订阅可接受；guest 当前不能创建这些动态内核资源，因此流为空，不制造 BPF 事件。BPF-output 计数仍不支持。

## 原版输入

- 官方 Alpine v3.22 `perf-6.15.0-r0`，未修改二进制、依赖或预期；`perf` ELF SHA-256：`2319203f347bb6523d28b9d0f7b816faf86723bc45dc5bda02c8fe87cb4f3cea`。用 apk 的签名校验安装，完整包清单保存在 `target/local-ci/io/perf-20261127/alpine-tool.json`（产品仓库工作区）。
- 原版工具与同一 ARM64 ABI ELF 对照 Lima 原生 Linux 7.0.0-44、Trames 解释器、Mac HVF。测试来自本仓库 [perf-tools.c](../../tests/fixtures/perf-tools.c) 和 [有界驱动](../../tests/perf/run.py)，不替换 perf 的事件实现和结果输出。
- 语义依据为 Linux v7.0 `kernel/events/core.c`、`ring_buffer.c`、UAPI、`fs/exec.c` 和原版 perf 文档。[原版事件实现](https://kernel.googlesource.com/pub/scm/linux/kernel/git/torvalds/linux/+/v7.0/kernel/events/core.c)与[环实现](https://kernel.googlesource.com/pub/scm/linux/kernel/git/torvalds/linux/+/v7.0/kernel/events/ring_buffer.c)的下载地址／原始哈希纳入 JSON 回执，原文件保留在产品工作区 `target/validation-perf-20261127/linux-source`。
- 缓存的原版 gVisor syscall 集合没有对应 perf 程序，本轮不增加 gVisor 全量通过身份；未改动领域的原始记录复用。

原版工具命令：

```sh
perf stat -e task-clock,context-switches,cpu-migrations,page-faults -- /opt/trames-perf/perf-tools cpu 500000
perf record -e task-clock:u -F 99 -m 8 --no-buildid --no-buildid-cache -o /results/perf.data -- /opt/trames-perf/perf-tools cpu 5000000
perf script -i /results/perf.data
```

这些命令显式选择软件时钟并关闭 build-id 收集，不请求硬件 PMU／callchain。保留工具对未提供 PMU sysfs 目录的诊断输出。`stat` 还检查实际触页计数，`script` 必须解析出 guest 工作负载与 task-clock 样本，不能只凭退出码通过。

## 验证记录

产品工作区证据根：`target/validation-perf-20261127`；Linux 原生证据：`target/local-ci/io/perf-20261127`。每个子命令有独立期限，保留超时／失败原输出，不以挂起一晚作为等待方式。

- ABI：value/enabled/running/id、组与 OFD、disable/reset、负 PID／cgroup FD 错误、真实匿名／COW 缺页、CPU 迁移、task+CPU／CPU-wide、远端任务退出冻结／HUP、cgroup 同名重建、提权 exec、新旧 context、采样／元数据和映射约束。
- 单槽：同一程序和原版工具在两种后端各使用唯一执行槽通过，阻塞工作交还现有执行槽。
- 初轮 Apple 2337 通过／1 失败／5 原有忽略，Linux 2348 通过／1 失败／5 原有忽略。两侧相同失败源于旧测试将 dump policy 当成只读查询；改为原 mm 续接的断言。随后两侧 53 项定向回归全部通过，后续 Memory/VFS、采样节奏、生命周期和未启用 perf 的快速路径统一补测后，按测试身份合并为 Apple 2,349 通过／5 原有忽略、Linux 2,360 通过／5 原有忽略。未变通过结果复用，不重复累加。
- 产品 conformance：554 通过／3 原有忽略；包含解释器采样预算的新回归。Apple/Linux Session 共享链严格 Clippy 和 iOS ARM64 构建通过；最终交付构建与逐项复用见 JSON 回执。
- 工具导入初始失败是驱动把文件交给只列目录的 `ls`、调试入口参数顺序及重复导入模式，不是 guest ABI 结果。使用原文件工具的 `put --replace` 更新工作负载后继续，保留原失败记录。没有修改原版工具。
- 原生参考纠正了 enabled/running 的错误假设；旧实现曾按 wall time 改 enabled，已撤回。原版 record 首轮暴露 ksymbol/BPF 订阅位与继承重新激活问题，整批修正后 stat/record/script 两后端通过，能够解析真实 guest PC 和 `hot` 符号。

- 恢复后的冷复制回归：同一 mm 的 helper 在 `read` 等待后丢弃目标页，排除首次预检已驻留的假阳性。保留的修正前 HVF 二进制稳定失败于“syscall continuation is excluded from user faults”；当前两后端唯一执行槽通过。另有 wire 回归确保内核样本不能携带 guest EL0 PC。
- 停用后迁移回归：先在 CPU 0 观察、关闭并继续执行，再迁移到 CPU 1，新开 CPU 0 过滤器。原生 Linux 通过，保留的修正前 HVF 失败于“task CPU filter excludes other CPU”；由原 actor 启动时钟后统一复验。

## 性能与交付

使用上一轮同步交付的固定二进制，串行交替对照无事件、计数、采样、禁用事件；另使用相同 ELF 的旧 futex／glibc 负载检查普通路径。首轮 160 条样本全部有效：无事件路径中位差为 +0.003%～+0.20%，HVF 采样为 −0.92%～+0.44%；解释器固定 1kHz 采样慢约 20.85%／21.13%。没有以功能通过覆盖该开销，已将临近截止时大量固定短片段改为实测速率校准，随后统一复测解释器受影响项；HVF 计时接口／测量路径未改，复用其首轮数据。

解释器首次改为截止前保守返回后，耗时改善但采样密度下降约 25%，该版本没有作为完成依据。最终预算略跨越预计截止时间，160 条固定工作样本全部有效，归一化采样密度相对旧版：解释器 1/4 CPU 为 1.012/1.012，HVF 为 1.990/1.986。HVF 旧版固定 2ms 返回，当前使用已有定时器接近请求的 1ms；增加的真实样本不是补造记录。最终耗时中位差如下（正值为更慢）：

| 后端／配置 | 无事件 | 计数 | 1kHz 采样 | 停用事件 |
| --- | ---: | ---: | ---: | ---: |
| 解释器 1 CPU | +2.44% | −0.82% | +0.24% | −0.65% |
| 解释器 4 CPU | +2.24% | −2.21% | −2.27% | −0.48% |
| HVF 1 CPU | +0.22% | −0.06% | +0.27% | +0.26% |
| HVF 4 CPU | +0.30% | +0.38% | +0.99% | −0.10% |

普通调用的同父版本对照单独暴露了未启用 perf 时反复进入采集入口的成本。已把从未使用 perf 的会话收敛为可内联的单原子提示，并去掉普通 syscall 完成后的重复探测。原先解释器 futex wake 增加 7.79%/7.07%，最终为 173.42→178.79ns（+3.10%）和 187.20→193.14ns（+3.17%）；仍有约 5–6ns 实测差值，不宣称零开销或将其抹掉。相同父版本对照产物来自干净的 `f10a159` Runtime／`e8542291` 产品归档，不混入 perf 修改。

固定工作量、校验和、预热、1/4 CPU 配置与全部样本保留在回执中，不把启动／镜像导入时间计入 guest 测量。相对上一轮固定交付版本的普通负载最终结果如下；wake/getcpu 是每次耗时（正值更慢），mutex 是吞吐（负值更慢），不把有升有降的吞吐结果概括为全部持平。

| 后端／配置 | futex wake 耗时 | glibc getcpu 耗时 | glibc mutex 吞吐 |
| --- | ---: | ---: | ---: |
| 解释器 1 CPU | +3.13% | +0.58% | -2.21% |
| 解释器 4 CPU | +2.61% | -0.46% | +0.31% |
| HVF 1 CPU | +0.49% | +0.00% | +0.75% |

每项均为五组交替配对的中位数。HVF 4 CPU mutex 本轮吞吐差 −4.67%，其余普通路径的差值同样保留；没有将这些观测解释为统计上已证明零回退。

Runtime 本轮快进整合已发布的 `f10a159`、`eefc3b2`，保留原提交身份。后者的共享内存增量为未被当前执行器调用的指令代次能力；JIT 库不在此次解释器／HVF 依赖链内。整合后重建两执行器与 iOS，并补共享链严格检查、定向单元和产品验证。最终 Runtime 与 iPad／Mac pin 按 main 配对交付；实际提交身份见产品 `runtime-version.json`。JSON 保存源码指纹、工具输入、逐项复用账本、失败反证和最终测量，原始输出保留在上述产品工作区。
