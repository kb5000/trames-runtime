# Interpreter job-control and sysfs fixture repairs

The interpreter kernel-conformance target now passes 502 tests with zero failures. Three manual performance probes remain ignored by the normal test command. All four previously failing assertions run and pass. The production session, scheduler, terminal and mount implementations retain the same source.

The terminal tests now give the background job a live shell parent in the same session and a different process group. Linux excludes global PID 1 as an outside parent when deciding whether a process group is orphaned. The old fixtures used PID 1 and therefore received the expected orphan-group behavior, including EIO on background terminal I/O or suppression of SIGTSTP. The four repaired tests still assert actual stop and continue delivery, one-slot execution, wait status, FD identity across close/reuse and a single seccomp decision for the retained ioctl. The thread-group test explicitly checks that its group is eligible to stop. [Linux orphan-group rules](https://codebrowser.dev/linux/linux/kernel/exit.c.html#351)

The prior interpreter gVisor command missed the writable sysfs setup used by the Mac harness. The default guest sysfs mount is read-only. In that setup, a child user namespace inherits the read-only restriction, so the original test's request for a writable sysfs mount correctly returns EPERM. The [interpreter harness](../../tests/gvisor/interpreter.py) now uses the same guest setup as the Mac harness and clones an isolated store for each case. Sysfs is made writable only in the disposable mount and rename test guests. Both original sysfs cases pass on the same interpreter executable used for the earlier mount-query run. The positive case allows mounting over an empty cgroup directory. The negative case still denies exposing a covered nonempty sysfs subtree.

The final interpreter run passes all 117 original `mount` and all 44 original `rename` cases. The Mac executor passes both original sysfs cases with the shared wrapper. Executable digests, the 161 original XML entries and the exact prior interpreter executable were checked. All 18 harness unit tests pass.

Run the interpreter kernel target from the iPad checkout with `cargo test -p trames-core --test kernel-conformance --locked --offline`. The gVisor README has the interpreter command and reference inputs. Local raw logs, the original per-case XML and runner fingerprints are under `target/interpreter-legacy` in the iPad checkout.
